# API Conventions & Guidelines

Veylix API adheres to strict RESTful design principles, deterministic JSON formatting, explicit HTTP status codes, and OpenAPI 3.1 documentation standards.

---

## 1. URL Naming & Resource Routing

- **Base URL**: `/api` (or `/api/v1` when versioned).
- **Resource Names**: Plural, lowercase, hyphen-separated kebab-case for multi-word paths (e.g., `/api/asset-movements`).
- **Identifiers**: CUID2 strings passed in the path (e.g., `/api/assets/:id`).

### Standard CRUD Endpoints

```http
GET    /api/assets              # List assets (paginated, filtered, sorted)
POST   /api/assets              # Create new asset
GET    /api/assets/:id          # Retrieve single asset details
PATCH  /api/assets/:id          # Update asset fields (mass-assignment protected)
DELETE /api/assets/:id          # Soft deactivate or remove (if unreferenced)
```

### Sub-Resources and Domain Actions

Domain actions that trigger business state machines or multi-entity workflows use explicit domain endpoints:

```http
POST   /api/assets/:id/transfers    # Transfer custody to another employee
POST   /api/assets/:id/maintenance  # Open maintenance work order
POST   /api/assets/:id/retire       # Transition status to RETIRED
GET    /api/assets/:id/movements    # List historical movement trail for asset
```

---

## 2. HTTP Methods & Status Codes

| Method   | Idempotent           | Usage                                     | Expected Success Status      |
| -------- | -------------------- | ----------------------------------------- | ---------------------------- |
| `GET`    | Yes                  | Read resources (no state changes)         | `200 OK`                     |
| `POST`   | No (unless with key) | Create resource or execute domain command | `201 Created` or `200 OK`    |
| `PATCH`  | Yes                  | Partial update of resource fields         | `200 OK`                     |
| `DELETE` | Yes                  | Deactivate/remove resource                | `200 OK` or `204 No Content` |

### Error Status Codes

- `400 Bad Request`: Validation failure or malformed payload.
- `401 Unauthorized`: Unauthenticated request (missing or invalid session).
- `403 Forbidden`: Authenticated user lacks required role/permission or violates object-level policy.
- `404 Not Found`: Resource does not exist.
- `409 Conflict`: Business invariant violation, unique constraint violation, or optimistic concurrency conflict.
- `422 Unprocessable Entity`: Semantic domain failure (e.g. invalid state transition).
- `429 Too Many Requests`: Rate limit exceeded.
- `500 Internal Server Error`: Unexpected unhandled error (sanitized in response).

---

## 3. Standard Request Headers

- `Content-Type`: `application/json`
- `Accept`: `application/json`
- `X-Request-Id`: Unique request correlation ID (`req_01J...`). Generated by client or assigned by API gateway middleware.
- `Idempotency-Key`: Optional UUID/CUID supplied by client on mutating POST commands (e.g., asset transfers).

---

## 4. Query Parameters (Pagination, Filtering, Sorting)

### 4.1 Pagination

Veylix supports both page-number pagination (for admin tables) and keyset cursor pagination (for high-volume feeds):

```http
# Page-based (Default for Data Tables)
GET /api/assets?page=1&limit=25

# Response Metadata Envelope:
{
  "data": [...],
  "meta": {
    "page": 1,
    "limit": 25,
    "totalItems": 1420,
    "totalPages": 57,
    "hasNextPage": true,
    "hasPreviousPage": false
  }
}
```

```http
# Keyset Cursor-based (For Audit Logs / Real-time Feeds)
GET /api/audit-logs?cursor=cuid_123456&limit=50
```

### 4.2 Filtering & Searching

- Standard filters: `?status=AVAILABLE&categoryId=cat_123&locationId=loc_456`
- Text search: `?search=MacBook+Pro` (matches patrimonyNumber, name, serialNumber)

### 4.3 Sorting

- Format: `?sort=createdAt:desc` or `?sort=patrimonyNumber:asc`

---

## 5. OpenAPI / Swagger Documentation

Every controller and DTO must be decorated with `@nestjs/swagger` annotations:

- `@ApiTags('Assets')`
- `@ApiOperation({ summary: 'Transfer asset custody to an employee' })`
- `@ApiResponse({ status: 200, type: AssetResponseDto })`
- `@ApiResponse({ status: 409, type: ErrorResponseDto })`
